# 小程序订单管理端使用说明

## 已实现的功能

- 只有云函数确认过的管理员才会在“我的”页面看到“订单管理”入口。
- 管理端适配手机竖屏，可筛选全部、未支付、未发货(已支付)、已发货、已完成、已取消订单。
- 支持标记已支付、确认发货和代用户完成订单，并在操作时再次由云函数验证管理员身份。
- 小程序前台每 30 秒检查一次新订单，发现新订单会震动并弹出提醒。
- 新订单创建后，云函数可向管理员发送微信订阅消息；关闭小程序后也能收到系统提醒。

## 一、设置管理员

管理员 ID 必须由服务端验证，不能只在前端写死。支持下面两种配置方式，任选一种即可。

### 方式 A：云数据库白名单（推荐）

1. 用管理员微信登录小程序。
2. 打开“我的 → 设置 → 我的用户 ID”，点击复制。
3. 在云开发控制台新建集合 `admin_users`。
4. 添加一条记录：

```json
{
  "openid": "这里填刚复制的用户 ID",
  "enabled": true
}
```

`admin_users` 只供云函数读取。建议把该集合的客户端读写权限都设为关闭，不要允许普通用户自行写入。

### 方式 B：云函数环境变量

给 `adminOrder` 和 `createOrder` 两个云函数都设置：

```text
ADMIN_OPENIDS=oXXXXXX,oYYYYYY
```

多个管理员 ID 使用英文逗号分隔。修改后重新进入小程序“我的”页面即可刷新入口。

## 二、配置微信订阅消息

### 1. 申请模板

1. 登录微信公众平台。
2. 进入“功能 → 订阅消息”。
3. 在公共模板库中选择适合“新订单提醒”的模板。
4. 在“我的模板”中复制模板 ID，并记录模板字段的 key，例如 `thing1`、`character_string2`、`amount3`、`time4`。

不同账号申请的模板字段可能不同，`ORDER_ADMIN_TEMPLATE_FIELDS` 必须与模板实际字段一致。

### 2. 配置 createOrder 云函数

在云开发控制台给 `createOrder` 设置以下环境变量：

```text
ORDER_ADMIN_TEMPLATE_ID=你的模板ID
ORDER_ADMIN_TEMPLATE_FIELDS={"thing1":"summary","character_string2":"orderNo","amount3":"totalPrice","time4":"createTime"}
ORDER_ADMIN_PAGE=pages/admin/orders
ORDER_MINIPROGRAM_STATE=formal
```

可用数据字段：

| 映射值 | 含义 | 建议模板字段类型 |
|--------|------|------------------|
| `summary` | 商品摘要，已截断为 20 个字符 | `thing` |
| `orderNo` | 订单号末 16 位 | `character_string` |
| `totalPrice` | 订单金额，如 `99.00` | `amount` |
| `createTime` | 下单时间 | `time` |

示例中的 key 只是演示，请换成你的模板实际 key。修改后重新上传并部署 `createOrder`。

### 3. 配置 adminOrder 云函数

给 `adminOrder` 设置同名模板 ID：

```text
ORDER_ADMIN_TEMPLATE_ID=你的模板ID
```

上传并部署 `adminOrder`。管理端“开启提醒”按钮会读取这个值并调用 `wx.requestSubscribeMessage`。

### 4. 管理员授权

进入“我的 → 订单管理 → 开启提醒”，在微信弹窗中允许订阅。

微信订阅消息必须由用户主动授权，代码不能绕过。若模板是一次性订阅模板，每次授权通常只能发送一次提醒；需要时再次点击“重新授权”。部分符合条件的行业可申请长期订阅模板，请以微信公众平台实际提供的模板为准。

## 四、提醒机制说明

### 小程序在前台

App 每 30 秒调用一次 `adminOrder` 检查待办订单。检测到待办变化后会：

工作台“待办”分别显示：

- 未支付：`pending` 数量。
- 未发货：`paid` 数量。

1. 让手机震动；
2. 弹出订单金额和待办数量；
3. 在“我的”Tab 显示红点；
4. 管理员入口显示待办数量。

### 小程序关闭或切到后台

小程序内的定时器会暂停，此时依靠微信订阅消息。要收到系统通知，需要同时满足：

- 管理端已经点击并允许“新订单提醒”；
- `createOrder` 已配置正确的模板 ID 和字段映射；
- 当前订阅授权仍有可用发送次数。

如果只能在 App 内提醒，通常是模板未配置、管理员未授权，或一次性订阅次数已用完。请查看 `createOrder` 云函数日志中的 `43101` 或字段校验错误。

## 五、订单操作规则

| 当前状态 | 管理端可执行操作 | 操作后状态 |
|----------|------------------|------------|
| `pending` 未支付 | 标记已支付 | `paid` 未发货(已支付) |
| `paid` 未发货(已支付) | 确认发货 | `shipped` 已发货 |
| `shipped` 已发货 | 用户确认收货，或管理员代完成 | `completed` 已完成 |

支付由客户和管理员私下完成，小程序不发起真实支付，只记录 `paid` 状态。用户端不能自行调用旧支付接口修改状态。管理员负责标记已支付和发货；用户收到商品后可在“我的订单”中确认完成，用户忘记时管理员也可以代完成。管理操作通过事务执行，并在云函数内验证管理员身份和当前状态。普通用户即使手动打开管理页，也无法查询全部订单或修改订单状态。
